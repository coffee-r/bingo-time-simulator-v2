# Bingo time simulator v2

パーティーや宴会のビンゴ大会が何分かかるかを見積もるツール。
[旧版（Nuxt）](https://github.com/coffee-r/bingo-time-simulator) を Cloudflare Workers + Hono で作り直した。

- サーバー: Hono（Cloudflare Workers）。ページの SSR とセキュリティヘッダーだけを担当する
- 計算: ブラウザの Web Worker を複数並列に動かしてモンテカルロ・シミュレーションする
- UI: `hono/jsx/dom`（外部ライブラリなし）

## 開発

```bash
npm install
```

```bash
npm run preview   # クライアントをビルドして wrangler dev（http://localhost:8787）
```

```bash
npm test          # ロジックのテスト（厳密計算との突き合わせを含む）
```

```bash
npm run deploy    # ビルドして Cloudflare にデプロイ
```

## ディレクトリ

```

  bingo.ts       カード生成・抽選・ビンゴ判定
  party.ts       宴会の進行（時間）モデル

  sample.ts      1回分の宴会を1球ずつ進める進行表

src/server/    Hono（SSR）
public/        静的アセット（style.css など。public/static はビルド成果物）
```

## 旧版のロジックの検証結果

ビンゴそのものの判定は正しかった。

- カード生成（各列 15個から5個を重複なく選ぶ）、Fisher–Yates シャッフル、縦横斜め12ラインの判定、中央フリーはいずれも正しい
- 「当選者は抜ける」の扱いも、累計ビンゴ人数で判定しているので結果的に正しい

ただし、見積もりとしては次の問題があった。

| 問題 | 影響 | v2 での対応 |
| --- | --- | --- |
| 100回の試行の **最小〜最大** を表示 | 両端の外れ値なので、実行のたびに大きくぶれる。幅も実態より広く見える | 試行を 10,000回に増やし、「10回に8回はおさまる範囲」（10〜90パーセンタイル）を表示 |
| 分を `Math.floor` で切り捨て | 最大値を切り捨てるので楽観側に寄る（例: 32分59秒 → 32分） | 下限は切り捨て、上限は切り上げ |
| 計算がメインスレッドで、全カードを毎球判定 | 人数が多いと画面が固まる | 各カードの「ビンゴになる球」を直接求める O(人数) の方式にし、Web Worker で並列化 |
| 景品0個の入力を許容 | 1球だけ引いて終了という不自然な結果 | 入力値の範囲をチェック |

入力項目は v1 と同じ4つ（参加人数・景品数・1回の抽選の時間・1回の当選の時間）に絞っている。
一時期はビンゴの確認・ジャンケン・開始前の説明・不参加率・中央フリーの有無・テンポのプリセットも入力できたが、
入力が多いと使いにくく、結果の差も「1回の当選の時間」を少し長めにすれば吸収できる程度だったので外した。

## 精度の担保

`test/exact.test.ts` で、シミュレーションの核である「k人目のビンゴが何球目までに出るか」の分布を厳密計算と突き合わせている。

厳密計算の考え方:

1. d 球引いた時点で、各列（B/I/N/G/O）から何個ずつ出たか (a1..a5) は多変量超幾何分布に従う
2. (a1..a5) が決まれば、1枚のカードがビンゴ済みである確率 p は、12ラインの包除原理と `C(a, m) / C(15, m)` で厳密に求まる
3. 列ごとの出方を固定すると各カードは独立なので、ビンゴ人数は Bin(N, p)
4. これを (a1..a5) の全組み合わせ（16^5 通り）で平均する

シミュレーション 40,000回の経験分布と厳密解のコルモゴロフ–スミルノフ距離が、有意水準 1% の許容値内に収まることを確認している。
1枚のカードが最初にビンゴになるまでの球数は、厳密計算で平均 41.37球（中央フリーなしは 43.55球）。一般に言われる「1枚なら約41球」と一致する。

さらに `test/independent.test.ts` で、本体とコードを一切共有しない素朴な実装（2次元配列のカードに1球ずつ穴をあけて縦横斜めをループで判定、別の乱数）と、所要時間の分布・ジャンケンになる確率を突き合わせている。
「斜め1本を判定から外す」といったバグをわざと入れると、このテストが失敗することも確認済み。

## 時間モデル

```
所要時間 = 抽選した回数 × 1回の抽選の時間 + 当選者数 × 1回の当選の時間
```

- 真ん中のマスは最初から開いている（固定）
- 最後の球で当たった人が残りの景品より多いときはジャンケンなどで決めるが、その時間は別に数えない。起きる確率だけ表示する
- ルール説明などの時間は含まない

既定値は 1回の抽選 20秒・1回の当選 60秒。

- 1回の抽選 20秒 = ガラガラを回す 5秒 + 番号の読み上げと復唱 5秒 + 参加者が探して穴をあける 10秒
- 1回の当選 60秒 = 「ビンゴ！」の申告と呼び出し 15秒 + 前に出てカード確認 15秒 + 景品の受け取り 15秒 + 席に戻る・拍手 15秒

### 実際の宴会の報告との比較

ネット上の報告と、同じ条件（秒数の記載がないものは既定値）での計算結果。報告は個人の体験談で、秒数などの条件がそろっていないので目安。

| 報告 | 条件 | 報告された時間 | このツール（10回に8回の範囲） |
| --- | --- | --- | --- |
| 二次会の進行記事 | 景品 × 1.5〜2分（一言なし）、× 2〜2.5分（一言あり） | 50人・景品10個なら 15〜25分 | 19〜22分（既定値） |
| 同上 | 100人・景品20個 | 40分〜1時間 | 30〜32分（既定値）／ 35〜38分（抽選30秒・当選60秒） |
| 知恵袋（2012） | 約60人・景品15個弱、前に出て選んで一言 | 20〜30分 | 25〜28分（既定値） |
| 知恵袋（2013） | 景品10個の二次会、1人約3分（一言・撮影） | 約1時間 | 30人なら 41〜44分（当選180秒） |
| 知恵袋（2022） | 300人・景品6個・抽選40秒（別のシミュレーターの結果） | 平均23分（17〜26分） | 17〜21分（当選60秒） |

一言・記念撮影がある会では「1回の当選」を 2〜3分にすると報告に近くなる。
